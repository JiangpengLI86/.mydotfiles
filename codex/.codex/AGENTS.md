# Global Agent Instructions

## Git and Version Control

- Always use `git commit --signoff` for all commits.
- Never add AI attribution to commits or pull requests. This includes `Co-Authored-By` trailers, "generated by" footers, or any mention of AI assistants in commit messages, PR titles, or PR descriptions.
- Never push, merge, or force-push without explicit user approval.
- Commit in logical splits: one commit per coherent change, not one giant squash.

## Documentation

- Always update README files and relevant documentation when changing public interfaces, CLI flags, directory structure, or configuration formats.
- Do not wait to be asked. If a change is visible to other developers, the docs should reflect it.

## Code Review

- When asked to fix code review findings, address ALL items completely in a single pass.
- Do not fix a subset and silently skip the rest.
- Before committing, verify every listed item has been resolved.

## Response Style

- When the user asks how to do something in a specific context (e.g., GitHub UI, a particular tool), provide instructions for that exact context. Do not generalize to other environments unless asked.
- Use clear, descriptive naming for variables, functions, files, and branches. Avoid misleading or jargon-heavy names.
- Prefer config-first changes: modify configuration before writing new code when the configuration layer can already solve the problem.

## Skills

Reusable skills for common git and GitHub workflows are available in `~/.codex/skills/`:

- `git-plan-commits` — plan and create clean local commits from a modified worktree
- `github-address-pr-comments` — fetch, triage, and address pull request review comments
